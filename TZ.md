# Техническое задание: MovieList

**Тип проекта:** учебное веб-приложение с frontend и backend.  
**Команда:** два разработчика.  
**Основной стек:** Next.js 16, React 19, JavaScript, CSS, SQLite, Node.js 24.x.  
**Версия документа:** 1.0.

## 1. Назначение проекта

Разработать сайт, на котором пользователь ведет список фильмов: добавляет интересующие фильмы, отмечает просмотренные и сохраняет собственную оценку. Проект должен показывать полный путь данных от формы в браузере до записи в базе.

Результат работы: запускаемый проект Next.js, backend API, локальная база SQLite, исходники в Git-репозитории, README.md и это техническое задание.

## 2. Пользователь и сценарий

Пользователь — человек, которому нужен простой список фильмов. Он открывает приложение, добавляет фильм, позднее меняет его статус на «Просмотрено», выставляет оценку и при необходимости находит запись через поиск.

В первой версии используется один общий список. Регистрация, роли администратора и разделение списка между аккаунтами в объем этой версии не входят.

## 3. Страницы и интерфейс

Главная страница `/` должна содержать:

1. Название MovieList и короткое описание назначения сайта.
2. Статистику по списку фильмов.
3. Поле поиска по названию.
4. Фильтры по жанру и статусу, выбор сортировки.
5. Карточки фильмов с названием, годом, жанром, статусом и оценкой.
6. Кнопку добавления фильма и форму добавления/редактирования.
7. Действия редактирования, смены статуса и удаления.
8. Понятные состояния загрузки, пустого списка и ошибки.

Интерфейс должен оставаться читаемым на телефоне и компьютере. Поля формы должны иметь подписи. Кнопки должны быть доступны с клавиатуры; при открытии диалога фокус должен переходить в него.

## 4. Функциональные требования

| Код | Требование | Ожидаемое поведение |
| --- | --- | --- |
| F01 | Получение списка | Фильмы загружаются с backend через `GET /api/movies` |
| F02 | Добавление | Корректная форма создает новую запись; карточка появляется в списке |
| F03 | Редактирование | Изменения сохраняются для выбранного `id` |
| F04 | Удаление | После подтверждения запись удаляется из базы и интерфейса |
| F05 | Статус просмотра | Доступны `planned`, `watching`, `watched` |
| F06 | Оценка | Можно сохранить целое число от 1 до 10 или оставить `null` |
| F07 | Поиск | Поиск по части названия работает без учета регистра, включая кириллицу |
| F08 | Фильтры | Жанр и статус можно применять совместно с поиском |
| F09 | Сортировка | Доступны порядок добавления, название, год и оценка |
| F10 | Хранение | Изменения сохраняются после обновления страницы и перезапуска сервера |
| F11 | Проверка данных | Ошибочные данные не попадают в базу; сервер возвращает понятную ошибку |
| F12 | Примеры | При создании базы добавляются шесть примеров; удаленные примеры не восстанавливаются автоматически |

Поиск, фильтрация и сортировка поддерживаются API. Их контракт остается одинаковым для всех обращающихся к серверу клиентов.

## 5. Модель данных

Основная сущность — `Movie`, один фильм.

| Поле | Тип | Ограничение и назначение |
| --- | --- | --- |
| `id` | Целое число | Положительный уникальный номер; назначает сервер |
| `title` | Строка | Обязательное название, после удаления пробелов по краям от 1 до 100 символов |
| `year` | Целое число | Обязательный год от 1888 до 2100 |
| `genre` | Строка | Одно значение из разрешенного списка |
| `status` | Строка | `planned`, `watching` или `watched`; при создании по умолчанию `planned` |
| `rating` | Целое число или `null` | От 1 до 10 либо отсутствие оценки; при создании по умолчанию `null` |
| `description` | Строка | Личная заметка, до 1000 символов; при создании по умолчанию пустая строка |
| `createdAt` | Строка даты ISO | Дата создания, назначает сервер |
| `updatedAt` | Строка даты ISO | Дата последнего изменения, назначает сервер |

Жанры: «Фантастика», «Драма», «Комедия», «Триллер», «Боевик», «Мультфильм», «Другое».

| Значение в API | Название в интерфейсе |
| --- | --- |
| `planned` | Хочу посмотреть |
| `watching` | Смотрю |
| `watched` | Просмотрено |

Одинаковые названия допускаются: у разных фильмов могут совпадать названия. Различие записей определяется `id`.

## 6. Backend и API

Backend реализуется средствами Next.js в файлах `route.js`. Отдельное приложение Express для этой версии не требуется. API работает в Node.js runtime и обращается к SQLite через `lib/database.js`.

### 6.1. Маршруты

| Метод | Маршрут | Действие | Успешный ответ |
| --- | --- | --- | --- |
| `GET` | `/api/movies` | Список фильмов | `200`, `{ "movies": [...] }` |
| `GET` | `/api/movies/[id]` | Один фильм | `200`, `{ "movie": {...} }` |
| `POST` | `/api/movies` | Создать фильм | `201`, `{ "movie": {...} }` |
| `PATCH` | `/api/movies/[id]` | Изменить переданные поля | `200`, `{ "movie": {...} }` |
| `DELETE` | `/api/movies/[id]` | Удалить фильм | `204`, пустое тело |

`[id]` заменяется настоящим номером: например, `/api/movies/3`.

### 6.2. Параметры списка

| Параметр | Пример | Назначение |
| --- | --- | --- |
| `q` | `интер` | Найти часть названия без учета регистра; до 100 символов |
| `genre` | `Фантастика` | Оставить один жанр |
| `status` | `watched` | Оставить один статус |
| `sort` | `newest`, `title`, `year`, `rating` | Выбрать порядок вывода |

Пример: `/api/movies?status=watched&sort=rating`. Параметры поиска формируются через `URLSearchParams`, чтобы корректно передавать кириллицу и пробелы.

По умолчанию используется `newest`: первыми идут недавно добавленные фильмы. `title` сортирует по названию по возрастанию, `year` — от новых годов к старым, `rating` — от высокой оценки к низкой; фильмы без оценки идут после оцененных.

### 6.3. Создание и изменение

В запросах `POST` и `PATCH` используется заголовок `Content-Type: application/json`.

Пример создания:

```json
{
  "title": "Дюна",
  "year": 2021,
  "genre": "Фантастика",
  "status": "planned",
  "rating": null,
  "description": "Посмотреть вместе на выходных."
}
```

Пример частичного изменения:

```json
{
  "status": "watched",
  "rating": 9
}
```

`PATCH` меняет только переданные поля. Клиент не задает `id`, `createdAt` и `updatedAt`. Неизвестные поля, невалидный JSON и неверные типы значений должны отклоняться.

### 6.4. Ошибки

Ошибки, которые формирует код API MovieList, возвращаются в формате `{ "error": "Понятное описание ошибки" }`. Исключение — автоматический ответ Next.js `405 Method Not Allowed` для неподдерживаемого метода: его тело может быть пустым.

| Код | Когда используется |
| --- | --- |
| `400` | Неверный формат данных, значение поля или идентификатор |
| `403` | Изменяющий запрос содержит `Origin` другого сайта |
| `404` | Фильма с указанным `id` нет |
| `405` | Для маршрута вызван неподдерживаемый HTTP-метод |
| `413` | JSON-тело превышает 16 КБ |
| `415` | Для JSON-запроса передан неподдерживаемый тип содержимого |
| `500` | Внутренняя ошибка сервера или работы с базой |

Сообщения `500` не должны раскрывать внутренние пути сервера или SQL-запросы. Ошибки запроса должны отображаться в интерфейсе; при ошибке сохранения данные формы должны оставаться доступными для исправления.

## 7. Хранение и ограничения

База хранится на сервере в `data/movielist.sqlite`. Папка создается автоматически. Необязательная переменная `MOVIELIST_DB_PATH` задает другой путь.

SQL-запросы с пользовательскими значениями должны использовать подготовленные выражения с параметрами. Проверка входящих данных выполняется на сервере независимо от проверки формы в браузере.

Локальная база и служебные файлы SQLite исключаются из Git. Каждый разработчик получает собственную базу при первом запуске. Для общего списка нужен один запущенный сервер, к которому обращаются оба клиента.

Первая версия не включает регистрацию, облачную синхронизацию отдельных аккаунтов, оплату, просмотр видео, внешние каталоги фильмов, загрузку постеров или рекомендательную систему. Для учебной демонстрации используются название, метаданные и заметки.

## 8. Организация проекта и работы

Все исходники находятся в одном Git-репозитории. `main` содержит проверенную рабочую версию. Основные рабочие ветки: `feature/frontend` и `feature/backend`.

| Участник | Ответственность | Что демонстрирует на защите |
| --- | --- | --- |
| Участник 1 | Компоненты React, CSS, формы, фильтры, запросы `fetch`, состояния интерфейса | Путь пользователя от кнопки до отправки запроса |
| Участник 2 | API, проверка полей, SQLite, HTTP-ответы, интеграционные проверки | Получение запроса, проверку и сохранение данных |
| Оба | Согласование полей, README, проверка всей цепочки, pull request | Как frontend и backend работают вместе |

План выполнения:

1. Согласовать поля фильма, маршруты API и структуру папок.
2. Подготовить репозиторий, зависимости и запуск приложения.
3. Реализовать backend и проверить запросы.
4. Реализовать интерфейс и подключить его к API.
5. Проверить совместную работу и сохранение данных.
6. Обновить README и подготовить демонстрацию.

Подробное распределение: [docs/TEAM.md](docs/TEAM.md).

## 9. Критерии приемки

Проект можно считать выполненным, если подтверждены следующие проверки:

- [ ] На Node.js 24.x выполняются `npm ci` и `npm run build`.
- [ ] `npm run dev` открывает рабочую страницу на `http://localhost:3000`.
- [ ] При первом обращении к новой базе появляются шесть примеров.
- [ ] Создание фильма возвращает `201`; запись видна в интерфейсе и через `GET`.
- [ ] Редактирование меняет именно выбранную запись, сохраняя ее `id`.
- [ ] Поиск находит фильм по части названия, включая другой регистр кириллицы.
- [ ] Фильтры по статусу и жанру работают вместе с поиском.
- [ ] Все варианты сортировки меняют порядок ожидаемым образом.
- [ ] Неверные данные, например пустое название или оценка `15`, отклоняются сервером.
- [ ] Неизвестный корректный `id` возвращает `404`.
- [ ] Удаление подтверждается пользователем; успешный запрос возвращает `204`.
- [ ] Фильм сохраняется после обновления страницы и остановки/повторного запуска сервера.
- [ ] Удаление всех записей оставляет пустой список и не запускает повторное заполнение примерами.
- [ ] На телефоне нет горизонтальной прокрутки основной страницы; формы и действия доступны.
- [ ] В Git отслеживаются исходники, lock-файл, README и ТЗ; зависимости, сборка и база исключены.
- [ ] Оба участника могут объяснить свою часть и цепочку «форма → API → SQLite → ответ».
