# Проверка ServiceDesk

Этот документ описывает воспроизводимые проверки. Ручные пункты ниже остаются чек-листом для вашего окружения.

Локально 23.10.2026 выполнены: unit-тесты — 9/9, production-сборка Next.js — успешно, интеграционные проверки на отдельной PostgreSQL — 12/12 (11 проверок и общий сценарий). Интеграционные тесты действительно перезапускали сервер и проверяли сохранённые заявки и комментарии. Workflow GitHub Actions подготовлен; удалённый запуск CI проверяется после публикации репозитория.

В браузере проверены вход демонстрационного администратора, Dashboard и отчёты с реальными графиками, фильтр статуса, карточка заявки, форма создания, меню профиля и сворачивание панели. Проверены ширины 1440, 768 и 390 px, переход из мобильного меню и закрытие по Escape с возвратом фокуса. Горизонтальная прокрутка ограничена таблицей; ошибок в консоли браузера при этой проверке не обнаружено. Локальная проверка выполнена на PostgreSQL 18.4; Compose и CI настроены на PostgreSQL 17.

## Автоматические проверки

```powershell
npm ci
npm run db:generate
npm test
npm run build
```

Интеграционные тесты требуют отдельной PostgreSQL-базы и собранного приложения. Настройте `TEST_DATABASE_URL`, примените к этой базе миграции и выполните `npm run test:integration`. Подробные команды находятся в [README](../README.md). Обычная рабочая база не должна использоваться для тестов.

Тесты проверяют запросы к настоящему серверу, авторизацию, разграничение прав, запись в PostgreSQL и чтение после перезапуска сервера. Они создают собственные записи с уникальными идентификаторами и удаляют только свои данные.

## Ручной сценарий

1. Зарегистрировать сотрудника, выйти и снова войти. Проверить профиль и завершение сессии.
2. Создать заявку с русским названием и описанием. Обновить страницу и проверить сохранение.
3. Проверить поиск, приоритет, статус, сортировку и переход из таблицы к деталям.
4. В отдельном профиле браузера открыть второго сотрудника: первая заявка ему недоступна.
5. Войти администратором, назначить исполнителя, проверить страницу команды.
6. Войти назначенным исполнителем, изменить статус и оставить комментарий.
7. Вернуться к сотруднику: проверить статус, комментарий и возможность ответа.
8. Сопоставить количество доступных заявок с Dashboard и отчётами. Создать или удалить одну заявку и проверить изменение показателей.
9. Проверить отклонение пустой формы, неправильного email, короткого пароля и некорректных значений API.
10. Выйти из аккаунта и открыть закрытый URL напрямую: приложение должно направить на вход, API вернуть ошибку доступа.

## Интерфейс

Проверьте ширины 1440, 768 и 390 px. У боковой панели одна кнопка сворачивания; навигация работает с клавиатуры. В таблице на телефоне допустима прокрутка самой таблицы. Проверьте открытие меню профиля, фокус полей, подписи, состояния загрузки, пустые списки и сообщения об ошибках. Уменьшите скорость соединения в DevTools, чтобы увидеть загрузку.

## Перед публикацией

Проверьте `git status`: `.env`, пароли, рабочая база и `.next` не должны попасть в коммит. Для сервера настройте отдельные секреты, HTTPS, PostgreSQL и запуск миграций перед новой версией. Демонстрационный seed запускается вручную, не при обычном старте приложения.
