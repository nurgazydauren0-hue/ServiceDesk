# Қорғауға арналған қысқа мәтін (қазақша)

Мәтінді дауыстап оқыңыз. **▶** белгісі бар жолдар — сол сәтте экранда не көрсету керек. Уақыты: шамамен 3–4 минут.

---

## 1. Кіріспе

Сәлеметсіз бе. Мен Дәуренмін, ServiceDesk жобасында серверлік бөлік пен дерекқорға жауап бердім.

ServiceDesk — IT бөліміне өтінім беру жүйесі. Жүйеде үш рөл бар: **қызметкер** мәселе туралы өтінім жазады, **IT-маман** оны шешеді, **әкімші** жұмысты бөліп, есептерді қарайды.

## 2. Дерекқор

**▶ Neon → Tables.**

Барлық деректер **PostgreSQL 17** дерекқорында, **Neon** бұлтында сақталады. Сондықтан Амина екеуміз бір дерекқормен жұмыс істейміз.

Браузер дерекқорға тікелей қосылмайды. Сұраныс былай жүреді: бет → Next.js сервері → Prisma ORM → PostgreSQL. Дерекқордың құпиясөзі тек серверде, `.env` файлында, ол GitHub-қа жүктелмейді.

Негізгі кестелер бесеу:
- `User` — пайдаланушылар;
- `Category` — өтінім санаттары;
- `Ticket` — өтінімдер;
- `Comment` — өтінім бойынша хат алмасу;
- `SupportRequest` — қолдау орталығына жіберілген шағымдар мен сұрақтар.

**▶ GitHub → DATABASE.md → ER-диаграмма.**

Барлық байланыстар «бірден-көпке». Бір пайдаланушы көп өтінім жасайды, бір өтінімде көп пікір болады. Кестелер сыртқы кілттермен байланысқан, сондықтан жоқ санатқа немесе жоқ пайдаланушыға сілтеме жасау мүмкін емес.

Деректер қайталанбайды — бұл **үшінші қалыпты форма**.

## 3. Қауіпсіздік

**▶ SQL Editor → 2.2 сұранысы.**

Құпиясөз дерекқорда сақталмайды, тек оның **scrypt-хеші** сақталады. Хештен құпиясөзді қалпына келтіру мүмкін емес.

**▶ 4.1, 4.2, 4.3 сұраныстары.**

Әр рөл өз деректерін ғана көреді. Сервер әр сұранысқа рөлге сәйкес `WHERE` шартын қосады:
- қызметкер — тек өз өтінімдерін;
- IT-маман — өзіне тағайындалған өтінімдерді;
- әкімші — барлығын.

**▶ 5-бөлімдегі сұраныстар.**

Бұл сұраныстар әдейі қате, сондықтан әрқайсысы қатемен аяқталуы тиіс. Қосымшаны айналып өтсе де, дерекқор дұрыс емес деректі қабылдамайды. Мысалы, жоқ санат, қайталанған email немесе тізімде жоқ мәртебе.

## 4. Жаңа мүмкіндік — Қолдау орталығы

Өтінім — бұл мәселе, мысалы «принтер жұмыс істемейді». Ал пайдаланушы өтінімнің **шешілуіне көңілі толмаса** немесе әкімшіге **сұрағы** болса, ол **қолдау орталығына** жазады.

Ол үшін дерекқорға жаңа кесте қостық — **`SupportRequest`**. Қолдау орталығы сайтта **тек осы кестені** көрсетеді: сайтта не тұрса, дерекқорда да сол.

Өтініштің:
- **түрі** бар: шағым, сұрақ немесе сапасыз шешім;
- **мәртебесі** бар: жаңа → қаралуда → шешілді;
- өтінімге, авторға және жауап берген әкімшіге **сілтемесі** бар.

**▶ Қызметкер ретінде кіру → «Қолдау орталығы» → өтінімді, «Шағым» түрін таңдап, мәтін жазу → «Қолдау орталығына жіберу».**

Мен сайтта шағым жібердім.

**▶ Neon → SupportRequest кестесі → ⟳ жаңарту.**

Дерекқорда `OPEN` мәртебесімен жаңа жол пайда болды.

**▶ Әкімші ретінде кіру → «Қолдау орталығы» → жауап жазу → «Жауап беріп, жабу».**

Әкімші шағымды қарап, жауап береді. Жауапсыз жабу мүмкін емес — оны сервер тексереді.

**▶ SQL Editor → 3.5 сұранысы.**

Енді дерекқорда мәртебе `RESOLVED`, әкімшінің жауабы мен аты сақталды. Қызметкер жауапты өз бетінде және өтінім картасында көреді.

Сервердегі ережелер:
- тек өзі көре алатын өтінімге шағым жіберуге болады;
- бір өтінім бойынша бір адамда тек бір ашық өтініш болады;
- жауапты тек әкімші береді;
- IT-маман өзіне жазылған шағымды көрмейді.

## 5. Қорытынды

Қорытындылай келе: ServiceDesk дерекқоры реляциялық, үшінші қалыпты формада, кестелер сыртқы кілттермен байланысқан. Құпиясөздер хеш түрінде сақталады, құқықтар әр сұраныста серверде тексеріледі, құрылым миграциялар арқылы өзгереді. Ал қолдау орталығы — бұл `SupportRequest` кестесі: пайдаланушы шағым жібереді, әкімші жауап береді, сайтта не болса, дерекқорда да сол.

Назарларыңызға рахмет, сұрақтарыңызға жауап беруге дайынмын.

## Сұрақтарға қысқа жауаптар

| Сұрақ | Жауап |
| --- | --- |
| Неге PostgreSQL? | Деректер өзара байланысты, сыртқы кілттер мен транзакциялар керек. |
| Бастапқы кілт деген не? | Жолды бірегей анықтайды, мысалы `Ticket.id`. |
| Сыртқы кілт деген не? | Басқа кестенің бастапқы кілтіне сілтеме: `Ticket.categoryId` → `Category.id`. |
| Транзакция деген не? | Не толық орындалатын, не мүлде орындалмайтын операциялар тобы. |
| Миграция деген не? | Дерекқор құрылымын өзгертетін SQL файл. Жаңа кесте миграциямен қосылды. |
| Индекс не үшін керек? | Бүкіл кестені қарап шықпай, жолды тез табу үшін. |
| Қолдау орталығы қайда сақталады? | `SupportRequest` кестесінде. Өтінімді өшірсе, оған қатысты өтініштер де өшеді (CASCADE). |
