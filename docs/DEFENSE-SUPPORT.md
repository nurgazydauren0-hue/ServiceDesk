# Центр поддержки: что добавили и как работает

Короткий текст для защиты, около 2 минут. Читайте вслух, строки с **▶** — что показать.

## Идея

Заявка — это проблема: «не работает принтер». А если пользователь **недоволен тем, как решили заявку**, или у него **вопрос к администратору**, он пишет в **центр поддержки**.

Для этого в базе есть отдельная таблица **`SupportRequest`** — обращения в центр поддержки. Центр поддержки на сайте показывает **только эту таблицу**: сколько строк в базе, столько обращений на странице. Обычные заявки остаются в разделе «Заявки».

## Таблица SupportRequest

| Поле | Что хранит |
| --- | --- |
| `id` | номер обращения: SR-0001, SR-0002… |
| `ticketId` | по какой заявке (FK → Ticket, **CASCADE**: удалили заявку — удалились и обращения) |
| `authorId` | кто написал (FK → User, **RESTRICT**) |
| `type` | ENUM: `COMPLAINT` — жалоба, `QUESTION` — вопрос, `QUALITY` — некачественное решение |
| `status` | ENUM: `OPEN` — новое → `IN_REVIEW` — на рассмотрении → `RESOLVED` — решено |
| `message` | текст обращения |
| `response` | ответ администратора |
| `handledById` | какой администратор ответил (FK → User, **SET NULL**) |
| `createdAt`, `updatedAt`, `resolvedAt` | когда создано, изменено и решено |

Миграция `20261126000000_support_requests` только добавила таблицу. Существующие данные не менялись.

## Правила на сервере

- Отправить можно только заявку, которую пользователь имеет право видеть.
- По одной заявке у одного человека — одно открытое обращение. Следующее можно отправить после ответа.
- Рассматривает и отвечает **только администратор**. Закрыть обращение без ответа нельзя.
- Сотрудник и исполнитель видят только свои обращения. Исполнитель не видит жалобу на себя.

## Кнопки — сотрудник и ИТ-специалист

**▶ Войти как сотрудник → «Центр поддержки».**

| Где | Кнопка | Что делает |
| --- | --- | --- |
| Центр поддержки, блок «Новое обращение» | выбор заявки, тип, текст → **«Отправить в центр поддержки»** | создаёт строку в `SupportRequest` со статусом `OPEN` |
| Карточка заявки, сверху | **«В центр поддержки»** | прокручивает к блоку центра поддержки в заявке |
| Карточка заявки, блок «Центр поддержки» | **«Отправить в центр поддержки»** | то же окно, но заявка уже выбрана. Пока нет ответа, кнопка неактивна |
| Блок «Мои жалобы и вопросы» | — | свои обращения: статус и ответ администратора |

**▶ Отправить жалобу → в Neon открыть Tables → SupportRequest → обновить ⟳: появилась строка.**

## Кнопки — администратор

**▶ Войти как администратор → «Центр поддержки».**

| Элемент | Что делает |
| --- | --- |
| 5 счётчиков | новые, на рассмотрении, открытые жалобы, решено сегодня, всего — это `COUNT` по таблице |
| Вкладки **«Открытые / Новые / На рассмотрении / Решённые»** и список **«Все типы»** | фильтруют обращения по статусу и типу |
| **«Взять в рассмотрение»** | статус `OPEN` → `IN_REVIEW` |
| Поле ответа + **«Ответить и закрыть»** | сохраняет ответ, статус → `RESOLVED`, заполняются `handledById` и `resolvedAt` |
| **«Открыть заявку»** | переход к заявке, на которую жалуются |
| **«Обновить»** | перезагружает данные |

**▶ Ответить и закрыть → в SQL Editor запустить 3.5: статус `RESOLVED`, есть ответ и администратор.**

## Как это работает технически

1. Кнопка отправляет `POST /api/tickets/{id}/support-requests` с типом и текстом.
2. Сервер проверяет данные (Zod), права на заявку и нет ли уже открытого обращения. Всё это в одной транзакции `Serializable`.
3. Prisma вставляет строку в `SupportRequest`.
4. Администратор отвечает через `PATCH /api/support/requests/{id}`. Этот маршрут доступен только роли `ADMIN`.
5. Страница центра поддержки получает данные из `GET /api/support`: администратор — все обращения, остальные — только свои.

Проверено тестами, в том числе интеграционным тестом прав на настоящей PostgreSQL.

**Одной фразой:** «Центр поддержки — это таблица `SupportRequest`. Пользователь отправляет жалобу или вопрос по заявке, сервер проверяет права и записывает строку, администратор рассматривает и отвечает. Что на сайте, то и в базе».
