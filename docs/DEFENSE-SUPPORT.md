# Центр поддержки: что добавили и как работает

Короткий текст для защиты, около 2 минут. Читайте вслух, строки с **▶** — что показать.

## Что было и что стало

Раньше страница «Поддержка» повторяла список заявок: та же таблица, только с вкладками по статусам. Мы сделали из неё отдельный **центр поддержки**. Он отвечает не на вопрос «какие заявки есть», а на вопрос **«кто кого ждёт»**.

У каждой роли свой экран:
- **администратор** — «Центр поддержки», пульт всей линии поддержки;
- **ИТ-специалист** — «Моя очередь поддержки»;
- **сотрудник** — «Центр помощи».

## Как это работает

Для этого расчёта отдельная таблица не нужна. Сервер берёт у каждой открытой заявки последний комментарий переписки и решает:
- последним написал пользователь или ответов ещё нет — **ждёт ответа поддержки**;
- последним написал специалист — **специалист работает**;
- статус «Ожидание» — **ждём пользователя**.

У каждого приоритета есть норма первого ответа: срочный — 2 часа, высокий — 8, средний — 24, низкий — 72. Если пользователь ждёт дольше нормы, обращение **просрочено** и поднимается наверх с красной меткой.

Код логики — `lib/support-center.js`, данные отдаёт `GET /api/support`. Тот же расчёт на SQL — запрос 3.5 в `database-demo.sql`.

## Новая таблица: жалобы и вопросы

Чтобы пользователь мог пожаловаться или задать вопрос по заявке, мы добавили в базу таблицу **`SupportRequest`** — обращения в центр поддержки. Миграция `20261126000000_support_requests` только добавляет таблицу и существующие данные не меняет.

- **Тип** (ENUM): жалоба, вопрос, некачественное решение.
- **Статус** (ENUM): новое → на рассмотрении → решено.
- **Связи:** заявка (CASCADE — удалили заявку, удалились и обращения), автор (RESTRICT), администратор, который ответил (SET NULL).
- **Правила на сервере:** отправить можно только заявку, которую видишь; одно открытое обращение на заявку от одного человека; обрабатывает и отвечает только администратор; закрыть без ответа нельзя; исполнитель не видит жалобу на себя.

**▶ Открыть любую заявку → внизу блок «Центр поддержки» → «Отправить в центр поддержки».**

| Где | Кнопка | Что делает |
| --- | --- | --- |
| Карточка заявки, сверху | **«В центр поддержки»** | прокручивает к блоку центра поддержки |
| Блок «Центр поддержки» в заявке | **«Отправить в центр поддержки»** | открывает окно: выбрать тип и описать ситуацию → `POST /api/tickets/{id}/support-requests`. Пока на обращение не ответили, кнопка неактивна |
| Окно отправки | **«Отправить» / «Отмена»** | создаёт запись в `SupportRequest` со статусом «Новое» |
| Центр поддержки администратора, блок «Жалобы и вопросы» | **«Взять в рассмотрение»** | статус → «На рассмотрении» |
| Там же | поле ответа + **«Ответить и закрыть»** | сохраняет ответ, статус → «Решено», заполняются `handledById` и `resolvedAt` |
| Там же | **«Открыть заявку»** | переход к заявке, на которую жалуются |
| Центр помощи сотрудника / очередь ИТ-специалиста | блок «Мои жалобы и вопросы» | свои обращения со статусом и ответом администратора |

**▶ В SQL Editor запустить 3.6** — обращение видно в базе вместе с заявкой, автором и администратором.

## Кнопки — администратор

**▶ Войти как администратор → «Центр поддержки».**

| Элемент | Что делает |
| --- | --- |
| 5 карточек сверху | ждут ответа, просрочено, без исполнителя, ждём пользователя, решено сегодня |
| Карточки «Без исполнителя» и «Ждём пользователя» | открывают список заявок с нужным фильтром |
| **Очередь ответов** | обращения, где пользователь ждёт ответа; просроченные и срочные сверху |
| Список **«Назначить…»** | назначает исполнителя прямо в карточке; рядом с именем — сколько у него открытых |
| **«Ответить»** | открывает заявку на поле комментария |
| Название заявки | открывает карточку заявки |
| **Загрузка ИТ-специалистов** | полоска нагрузки, сколько ждут ответа и сколько просрочено; щелчок — заявки этого специалиста |
| **Нужно назначить** | заявки без исполнителя с тем же списком «Назначить…» |
| **Лента переписки** | 5 последних сообщений: кто написал — пользователь или поддержка |
| **«Обновить»** | перезагружает данные |
| Внизу «Нормы первого ответа» | сроки по приоритетам |

## Кнопки — ИТ-специалист

**▶ Войти как исполнитель → «Центр поддержки».**

Три колонки: **«Нужен ответ»**, **«В работе»**, **«Ждём пользователя»**. В каждой карточке:

| Кнопка | Что делает |
| --- | --- |
| **«Взять в работу»** (только у новых) | меняет статус «Новая» → «В работе» |
| **«Ответить»** | открывает заявку на поле комментария; после ответа заявка переходит из «Нужен ответ» в «В работе» |
| **«Решена»** | ставит статус «Решена», в базе заполняется дата решения `resolvedAt` |

Специалист видит только назначенные ему заявки: это проверяет сервер.

## Кнопки — сотрудник

**▶ Войти как сотрудник → «Центр помощи».**

| Элемент | Что делает |
| --- | --- |
| Карточки тем (оборудование, сеть…) | открывают форму новой заявки с уже выбранной категорией |
| Зелёная полоса сверху | сообщает, что специалист ждёт ответа сотрудника |
| Метки в карточке | «Специалист ждёт вашего ответа», «Специалист работает над решением», «Ответим в течение …» |
| **«Ответить» / «Открыть»** | открывает заявку и переписку |
| **«Как это работает»** | 4 шага жизни обращения |
| **«Недавно решённые»** | последние закрытые обращения |
