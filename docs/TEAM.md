# MovieList: работа вдвоем

Цель — чтобы каждый участник понимал свою часть и мог объяснить, как она связана с другой. Имена можно вписать в таблицу перед сдачей.

| Участник | Имя | Основная роль | Рабочая ветка |
| --- | --- | --- | --- |
| 1 | ____________________ | Frontend | `feature/frontend` |
| 2 | ____________________ | Backend и база данных | `feature/backend` |

## 1. Кто что делает

### Участник 1: frontend

Основные файлы: `app/page.jsx`, `app/layout.jsx`, `app/globals.css`, `components/movie-library.jsx`, `components/movie-card.jsx`, `components/movie-form.jsx`, `components/icon.jsx`.

- Страница MovieList, карточки и адаптивная верстка.
- Форма добавления и редактирования с подписями полей.
- Поиск, фильтры, сортировка и статистика.
- Отправка запросов через `fetch` и обновление списка после действий.
- Отображение загрузки, ошибок и пустого состояния.
- Удобное управление диалогами и подтверждение удаления.

**Результат:** пользователь может выполнить все действия с фильмами через интерфейс.

### Участник 2: backend

Основные файлы: `app/api/movies/route.js`, `app/api/movies/[id]/route.js`, `lib/database.js`, `lib/movie-validation.js`, `lib/movie-constants.js`, `lib/api-errors.js`, `tests/api.test.mjs`.

- Создание SQLite-базы и начальных примеров.
- Обработка `GET`, `POST`, `PATCH`, `DELETE`.
- Проверка данных до записи в базу.
- Поиск, фильтрация и сортировка на сервере.
- Корректные HTTP-коды и сообщения об ошибках.
- Проверки API и сохранения данных после перезапуска.

**Результат:** API работает независимо от интерфейса и сохраняет данные в SQLite.

### Общая работа

Оба участника согласуют поля фильма до изменений, проверяют проект на своих компьютерах, читают pull request друг друга и обновляют README. На защите каждый показывает свою часть, затем вместе демонстрируют полный сценарий.

Изменения `package.json`, `package-lock.json` и общего API-контракта сначала обсуждаются: эти файлы и решения влияют на обе части проекта.

## 3. Git-правила

`main` — общая проверенная версия. Каждый работает в своей ветке. Изменения объединяются через pull request после просмотра вторым участником.

Перед началом работы:

```bash
git switch main
git pull --ff-only origin main
```

Первый участник один раз создает свою ветку:

```bash
git switch -c feature/frontend
```

Второй участник создает свою:

```bash
git switch -c feature/backend
```

При следующей работе с существующей веткой используется `git switch feature/frontend` или `git switch feature/backend` без `-c`.

После законченного изменения frontend:

```bash
git status
git add app/page.jsx app/layout.jsx app/globals.css components
git commit -m "feat: add movie form and filters"
git push -u origin feature/frontend
```

После законченного изменения backend:

```bash
git status
git add app/api lib tests
git commit -m "feat: add movie API and SQLite storage"
git push -u origin feature/backend
```

Команды `git add` добавляют только перечисленные пути. Если менялись документы, их нужно добавить отдельной командой, например `git add README.md TZ.md`.

На GitHub откройте **Pull requests → New pull request**, выберите `base: main` и свою рабочую ветку. В описании напишите, что изменилось и как проверяли. Второй участник читает изменения и проверяет работу перед объединением.

## 4. Как получить изменения напарника

Сначала сохраните свою текущую работу коммитом. Затем из своей рабочей ветки выполните:

```bash
git fetch origin
git merge origin/main
```

При конфликте откройте отмеченные файлы, вместе выберите правильный итоговый код, удалите маркеры конфликта и проверьте проект. После исправления добавьте затронутые файлы через `git add`, затем выполните `git commit`.

После объединения в `main` оба участника обновляют локальную `main` через `git pull --ff-only origin main`. Для следующей небольшой задачи удобно создать новую ветку, например `feature/search-fix`.

## 5. Что каждый должен уметь объяснить

| Вопрос | Кто объясняет первым |
| --- | --- |
| Как состояние React связано с формой и списком? | Frontend |
| Что отправляется в `fetch` при нажатии «Добавить»? | Frontend |
| Как сервер понимает, какую операцию выполнить? | Backend |
| Почему проверка полей нужна и на сервере? | Backend |
| Где находится база и почему данные остаются после перезапуска? | Backend |
| Как исправление доходит из рабочей ветки до `main`? | Оба |
| Как отследить весь путь одного фильма? | Оба |

Готовая основа проекта не заменяет разбор кода. Для самостоятельной доработки каждый может взять по одной небольшой задаче: например, frontend — улучшить пустое состояние, backend — добавить новый согласованный фильтр.
