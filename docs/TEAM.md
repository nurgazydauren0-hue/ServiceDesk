# ServiceDesk: работа двух участников

| Участник | Имя | Основная ответственность |
| --- | --- | --- |
| 1 | ____________________ | Frontend, UI и пользовательские сценарии |
| 2 | ____________________ | Backend, авторизация и PostgreSQL |

## Участник 1 — Frontend / UI

Основные области: страницы `app`, компоненты `components`, стили и адаптивность.

- Навигация с одной кнопкой сворачивания, верхняя панель и меню профиля.
- Dashboard, таблица заявок, поиск, фильтры, сортировка и графики Recharts.
- Формы входа, регистрации, создания заявки, комментариев и профиля.
- Страница деталей с действиями, соответствующими роли.
- Загрузка, пустые состояния, уведомления и читаемые ошибки.
- Работа с клавиатурой и адаптивная вёрстка.

Участник объясняет состояние React, передачу параметров фильтров, отправку JSON и обновление интерфейса после ответа. Он показывает реальную форму и соответствующий запрос в Network.

## Участник 2 — Backend / Database

Основные области: `app/api`, `auth.js`, серверные модули `lib`, `prisma`, `tests`.

- Модели, связи и миграции PostgreSQL через Prisma.
- Регистрация, scrypt-хеши паролей и сессии Auth.js.
- Проверка текущего пользователя и его роли на сервере.
- Zod-валидация, HTTP-ошибки и защита операций изменения данных.
- CRUD заявок, назначение исполнителя, комментарии и управление ролями.
- Агрегация данных Dashboard и отчётов в PostgreSQL.
- Отдельные bootstrap/seed и изолированные интеграционные тесты.

Участник объясняет путь запроса от API до базы, отличие хеша от исходного пароля, ограничения `where` для каждой роли и назначение миграций.

## Общая работа

Перед изменением API согласуйте адрес, метод, поля, ответ и коды ошибок. Не меняйте имена полей только в одном слое. Проверяйте работу в отдельной базе; не передавайте друг другу `.env` через Git.

У каждого своя рабочая ветка, например `codex/frontend` и `codex/backend`. Общая проверенная версия находится в `main`. Для объединения используйте pull request с описанием поведения и выполненных проверок. Напарник читает код и воспроизводит основной сценарий перед объединением.

```powershell
git switch main
git pull --ff-only
git switch -c codex/your-task
```

Перед коммитом проверьте `git diff`, `git status`, выполните unit-тесты и сборку. Изменения авторизации, ролей или API дополнительно проверяйте интеграционными тестами. В PR укажите фактически выполненные команды и их результат.

## Совместная демонстрация

Первый участник создаёт заявку от сотрудника и объясняет интерфейс. Второй показывает серверную проверку, запись Prisma и PostgreSQL, затем назначает исполнителя. Первый демонстрирует изменение статуса и комментарии. Второй показывает, что другой сотрудник не получает доступ к заявке даже прямым API-запросом. Вместе обновляют страницу и объясняют сохранение данных.

Каждый должен уметь самостоятельно установить проект по README, а также объяснить, какие изменения внёс лично.
