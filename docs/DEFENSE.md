# MovieList: подготовка к защите

## Как представить проект

«MovieList — сайт для списка фильмов. Пользователь добавляет фильм, отмечает статус просмотра, ставит оценку и ищет записи по названию или жанру. Интерфейс написан на React, приложение использует Next.js. Серверные маршруты принимают запросы и сохраняют данные в SQLite. Работа разделена между двумя участниками: frontend и backend».

Говорите своими словами и показывайте соответствующий экран или файл. По любому пункту нужно уметь объяснить реальный код проекта.

## Сценарий демонстрации на 5 минут

### 1. Назначение и интерфейс — около 40 секунд

Первый участник открывает страницу, показывает список, поиск, фильтры и кнопку добавления. Объясняет: «Пользователь хранит здесь фильмы, которые собирается посмотреть или уже посмотрел».

### 2. Добавление и запрос — около 1 минуты

Первый участник добавляет тестовый фильм с заметкой. В DevTools браузера открывает вкладку **Network** и показывает `POST /api/movies`.

Объяснение: «Форма хранит введенные значения в состоянии React. По нажатию кнопки `fetch` отправляет JSON на backend. При успешном ответе интерфейс обновляет список».

### 3. Backend и база — около 1 минуты

Второй участник показывает `app/api/movies/route.js`, функцию проверки данных и запрос в `lib/database.js`.

Объяснение: «Маршрут получает запрос, проверяет поля, добавляет запись в SQLite и возвращает созданный фильм с кодом `201`. Номер `id` назначает база».

### 4. Изменение, сохранение и ошибка — около 1,5 минуты

1. Измените статус фильма на «Просмотрено» и поставьте оценку.
2. Покажите запрос `PATCH` и обновленную карточку.
3. Обновите страницу: данные сохранятся.
4. Остановите сервер через `Ctrl+C`, запустите снова и покажите сохраненный фильм.
5. Продемонстрируйте один неправильный запрос, например оценку `15`, и ответ сервера `400`.

Для проверки ошибки можно использовать Postman или консоль браузера на странице приложения:

```js
fetch("/api/movies", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    title: "Проверка ошибки",
    year: 2024,
    genre: "Драма",
    status: "watched",
    rating: 15,
    description: ""
  })
}).then(async (response) => {
  console.log(response.status, await response.json());
});
```

Результат: сервер отклоняет оценку вне диапазона, фильм не создается. Это показывает, что проверка работает на backend, даже если запрос отправлен без формы.

### 5. Удаление и Git — около 50 секунд

Удалите тестовую запись с подтверждением. Покажите GitHub-репозиторий, README, ТЗ и изменения каждого участника. Коротко объясните, как рабочие ветки объединяются в `main` через pull request.

Если загрузка на GitHub еще не выполнена, сначала завершите шаги из [GITHUB.md](GITHUB.md); локальный репозиторий сам по себе не является ссылкой на GitHub.

## Основные вопросы и понятные ответы

| Вопрос | Ответ |
| --- | --- |
| Для чего нужен Next.js? | Он объединяет страницы React и серверные маршруты в одном проекте. |
| Где frontend? | В компонентах React, `app/page.jsx` и стилях. Он показывает данные и принимает действия пользователя. |
| Где backend? | В `app/api/.../route.js` и серверных функциях `lib`. Он проверяет запросы и обращается к базе. |
| Что такое API? | Согласованные адреса и правила запросов, через которые интерфейс общается с сервером. |
| Что делает GET? | Читает данные: список или один фильм. |
| Что делает POST? | Создает новую запись. |
| Что делает PATCH? | Изменяет переданные поля существующей записи. |
| Что делает DELETE? | Удаляет запись по ее `id`. |
| Что такое JSON? | Текстовый формат обмена данными; например объект с названием, годом и жанром. |
| Зачем каждому фильму id? | По этому номеру сервер находит конкретную запись, даже если названия совпадают. |
| Где сохраняются фильмы? | В серверном файле SQLite `data/movielist.sqlite`. |
| Почему не исчезают после обновления страницы? | Страница заново читает их из API, а API — из сохраненной базы. |
| Зачем серверная валидация, если есть форма? | К API можно обратиться напрямую; сервер обязан проверять любое полученное значение. |
| Почему SQL использует параметры? | Значения пользователя передаются как данные, отдельно от текста SQL-команды. |
| Чем отличаются Git и GitHub? | Git ведет историю изменений; GitHub хранит удаленный репозиторий и помогает работать вместе. |
| Зачем README? | Чтобы другой человек понял назначение проекта, структуру и команды запуска. |
| Зачем ТЗ? | Чтобы заранее определить функции проекта и проверить, что они выполнены. |
| Почему база не лежит в GitHub? | В Git хранится код, а локальные данные создаются при запуске и меняются отдельно. |

## Что повторить перед занятием

- Найти в коде один обработчик `fetch` и объяснить его метод, адрес и тело запроса.
- Найти соответствующий `route.js` и проследить путь до SQL.
- Объяснить разницу между состоянием React и сохраненной записью SQLite.
- Показать успешный и ошибочный HTTP-ответ.
- Самостоятельно запустить проект из README.
- Объяснить собственные изменения по истории Git.

## Честно обозначьте объем проекта

Первая версия использует один общий список и не содержит авторизации. Сайт показывает работу интерфейса, CRUD API и базы данных. Следующими улучшениями могут стать личные аккаунты, собственные подборки и внешний каталог фильмов, но на защите они должны называться планами, а не готовыми функциями.
