# Публикация ServiceDesk в GitHub

Публикация исходников и размещение работающего приложения — разные действия. GitHub хранит код и запускает CI. Для работы ServiceDesk нужен Node.js-сервер с доступом к PostgreSQL.

## Подготовка

Проверьте `git status` и `.gitignore`. Не добавляйте `.env`, пароли, дампы рабочей базы, зависимости, `.next` или локальные инструменты. В репозитории остаются `.env.example`, Prisma Schema, миграции и инструкции настройки.

Выполните проверки из [CHECKS.md](CHECKS.md). В README описывайте только работающие возможности и воспроизводимые команды.

## Удалённый репозиторий

Создайте пустой репозиторий `servicedesk` в своём аккаунте GitHub. Если локальный проект уже имеет Git-историю, сохраняйте её. Проверьте адреса:

```powershell
git remote -v
```

Если `origin` отсутствует:

```powershell
git remote add origin https://github.com/YOUR_USERNAME/servicedesk.git
```

Если `origin` существует, сначала убедитесь, что адрес относится к вашему репозиторию; при необходимости обновите его через `git remote set-url origin ...`.

После просмотра изменений создайте коммит и отправьте свою ветку:

```powershell
git status
git diff
# Добавьте только проверенные файлы проекта через git add.
git commit -m "feat: implement ServiceDesk"
git push -u origin YOUR_BRANCH
```

Замените `YOUR_USERNAME` и `YOUR_BRANCH` своими значениями. Не используйте `push --force` как обычный способ исправления ошибок. При запросе входа пройдите штатную процедуру GitHub, не записывая токен в URL репозитория.

## Работа второго участника

Владелец приглашает напарника в настройках доступа репозитория. После принятия приглашения напарник клонирует проект и выполняет README, включая собственную PostgreSQL-базу и `.env`:

```powershell
git clone https://github.com/YOUR_USERNAME/servicedesk.git
cd servicedesk
npm ci
```

Дальнейшие команды базы и запуска находятся в [README](../README.md), распределение работы — в [TEAM.md](TEAM.md).

## Что передать преподавателю

Ссылку на фактический GitHub-репозиторий, README, ТЗ, распределение работы и демонстрацию основного сценария. Проверьте, что CI завершился успешно именно для показываемого коммита. Локальный коммит сам по себе не означает, что код уже опубликован.
