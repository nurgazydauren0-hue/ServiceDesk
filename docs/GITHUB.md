# MovieList: GitRepo и GitHub

**Git** хранит историю изменений проекта на компьютере. **Git-репозиторий**, или GitRepo, — папка проекта вместе с этой историей. **GitHub** размещает удаленную копию репозитория и помогает работать вдвоем.

Файлы README и ТЗ уже находятся в проекте. На GitHub нужен репозиторий, в который будут отправлены исходники.

## 1. Подготовьте Git

В терминале VS Code выполните:

```bash
git --version
```

Если команда не найдена, установите [Git](https://git-scm.com/downloads) и заново откройте VS Code.

Откройте терминал в папке `movielist`, рядом с `package.json`.

## 2. Подготовьте локальный репозиторий

В комплекте `movielist-project.zip` находятся `movielist/` с исходниками без папки `.git` и файл `movielist.bundle` с начальной историей. Выберите один из двух вариантов ниже. Если репозиторий уже клонирован, переходите к разделу 3.

### Вариант А: начать историю из папки исходников

Выполняйте команды в распакованной папке `movielist`, рядом с `package.json`.

```bash
git init -b main
```

Укажите свое имя и адрес для коммитов. Настройки ниже относятся только к текущему репозиторию. Замените примеры собственными данными; вместо личного адреса можно использовать свой GitHub `noreply`-адрес из настроек GitHub.

```bash
git config user.name "YOUR_NAME"
git config user.email "YOUR_GIT_EMAIL"
git add .
git commit -m "feat: initial MovieList project"
```

`.gitignore` уже исключает зависимости, сборку, локальные настройки и базу. Перед коммитом полезно выполнять `git status`, чтобы видеть добавляемые файлы.

### Вариант Б: восстановить готовую историю из bundle

Откройте терминал в папке, где лежит `movielist.bundle`, и выполните:

```bash
git clone movielist.bundle movielist-from-git
cd movielist-from-git
```

Появится новая папка с исходниками, веткой `main` и начальным коммитом. Дополнительно выполнять `git init` и создавать первый коммит не нужно. Для своих последующих коммитов укажите данные автора:

```bash
git config user.name "YOUR_NAME"
git config user.email "YOUR_GIT_EMAIL"
```

После клонирования из bundle адрес `origin` указывает на локальный файл. Создайте пустой репозиторий по разделу 3, затем замените `origin` его реальным адресом:

```bash
git remote set-url origin https://github.com/YOUR_USERNAME/movielist.git
git push -u origin main
```

`YOUR_USERNAME` замените настоящим логином владельца репозитория. После успешного push переходите к разделу 5. Файл bundle сохраняет Git-историю; сам по себе он не создает репозиторий на GitHub.

## 3. Создайте пустой репозиторий на GitHub

1. Войдите в свой GitHub и откройте [создание репозитория](https://github.com/new).
2. В поле **Repository name** укажите `movielist`.
3. Описание: `Учебный проект Next.js: список фильмов с API и SQLite`.
4. Выберите видимость. Для учебного проекта можно начать с **Private**; доступ преподавателю и напарнику предоставляется отдельно.
5. Оставьте выключенным создание README. Не добавляйте `.gitignore` и лицензию на этом шаге: существующие файлы придут из проекта.
6. Нажмите **Create repository** и скопируйте HTTPS-адрес полученного репозитория.

Обычно адрес выглядит так: `https://github.com/YOUR_USERNAME/movielist.git`. `YOUR_USERNAME` — обозначение места для вашего настоящего логина, а не готовый адрес проекта.

## 4. Свяжите локальный проект с GitHub

Посмотрите текущие удаленные адреса:

```bash
git remote -v
```

Если вывода нет, добавьте адрес своего нового репозитория:

```bash
git remote add origin https://github.com/YOUR_USERNAME/movielist.git
git push -u origin main
```

Если `origin` уже существует, не добавляйте его повторно. Убедитесь, что это ваш проект; если адрес требуется заменить, выполните:

```bash
git remote set-url origin https://github.com/YOUR_USERNAME/movielist.git
git push -u origin main
```

При запросе входа используйте предложенную Git/GitHub процедуру авторизации. Пароли и токены не записывайте в исходники, README или адрес `origin`.

После успешной отправки обновите страницу репозитория: должны быть видны `README.md`, `TZ.md`, `package.json`, `app`, `components`, `lib` и остальные исходники.

## 5. Подключите второго участника

Владелец репозитория открывает настройки доступа GitHub и приглашает напарника по его точному логину. Напарник принимает приглашение в своем аккаунте.

Затем второй участник выполняет:

```bash
git clone https://github.com/YOUR_USERNAME/movielist.git
cd movielist
npm ci
npm run dev
```

В команде используется логин владельца общего репозитория. Два отдельных репозитория для этого проекта не нужны.

Распределение веток и pull request описано в [TEAM.md](TEAM.md).

## 6. Что передать преподавателю

- Ссылку на реальный GitHub-репозиторий после отправки кода.
- README с командами запуска.
- ТЗ и распределение задач.
- Демонстрацию работающего сайта и запросов API.

Публичность исходников и запуск сайта — разные вещи. Этот проект запускает backend в Node.js; обычная публикация файлов через GitHub Pages не запустит API и SQLite. Для защиты достаточно локального запуска. Для удаленного размещения потребуется хостинг Node.js с постоянным диском или отдельная база данных.

## 7. Частые сообщения Git

| Сообщение | Что проверить |
| --- | --- |
| `Author identity unknown` | Укажите `user.name` и `user.email` перед коммитом |
| `remote origin already exists` | Посмотрите `git remote -v`; при необходимости используйте `set-url` |
| `src refspec main does not match any` | Проверьте наличие первого коммита и название текущей ветки |
| `Repository not found` | Проверьте точный URL, вход в аккаунт и доступ к приватному репозиторию |
| `non-fast-forward` | На GitHub есть изменения, которых нет локально; получите их и разберите различия перед отправкой |

Если удаленный репозиторий случайно создали с отдельным README, сначала разберитесь с двумя историями. Не используйте `push --force` как обычный способ исправления.
