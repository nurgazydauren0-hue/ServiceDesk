# MovieList

**MovieList — учебный сайт для списка фильмов:** что хочется посмотреть, что уже смотришь и что посмотрел. Пользователь добавляет фильмы, меняет их статус, ставит оценку и находит нужное через поиск и фильтры.

Проект подходит для совместной работы двух студентов: один отвечает за интерфейс, второй — за API и базу данных. Обе части находятся в одном приложении Next.js.

## Что уже реализовано

- Просмотр списка фильмов и краткой статистики.
- Добавление, редактирование и удаление фильма.
- Статусы «Хочу посмотреть», «Смотрю», «Просмотрено».
- Оценка фильма от 1 до 10; можно оставить без оценки.
- Поиск по названию, фильтры по жанру и статусу, сортировка.
- Проверка полей на сервере и сообщения об ошибках.
- Сохранение в SQLite: данные остаются после обновления страницы и перезапуска сервера.
- Адаптивный интерфейс для компьютера и телефона.

При первом запуске база заполняется шестью примерами фильмов. После удаления всех фильмов примеры сами не восстанавливаются.

## Быстрый запуск

Понадобятся **Node.js 24.x**, npm и редактор, например VS Code. Для работы с репозиторием также нужен Git.

1. Распакуйте проект и откройте папку `movielist` в VS Code.
2. Откройте **Terminal → New Terminal**. Команды выполняйте в папке, где лежит `package.json`.
3. Проверьте Node.js и установите зависимости:

```bash
node --version
npm ci
```

Версия Node.js должна начинаться с `v24.`.

4. Запустите сайт:

```bash
npm run dev
```

5. Откройте [http://localhost:3000](http://localhost:3000). Оставьте терминал работающим. Чтобы остановить сервер, нажмите `Ctrl+C`.

Отдельно устанавливать SQLite, запускать второй backend-сервер или получать API-ключ не нужно. Файл базы `data/movielist.sqlite` появится автоматически при первом обращении к API.

Для обычного запуска `.env.local` не требуется. Если нужен другой путь к базе, скопируйте `.env.example` в `.env.local` и измените `MOVIELIST_DB_PATH`.

### Если PowerShell блокирует npm

Попробуйте в терминале VS Code использовать профиль **Command Prompt** либо команды `npm.cmd ci` и `npm.cmd run dev`.

## Как работает backend

Пример: пользователь добавляет «Интерстеллар».

1. Заполняет форму и нажимает «Добавить».
2. Компонент интерфейса отправляет `POST /api/movies` с данными в JSON.
3. Сервер проверяет название, год, жанр, статус и оценку.
4. Сервер сохраняет запись в SQLite и возвращает новый фильм с `id`.
5. Интерфейс обновляет список и показывает созданную карточку.

Браузер обращается к API. Сам файл SQLite читает и изменяет серверный код.

## API

| Метод | Адрес | Действие |
| --- | --- | --- |
| `GET` | `/api/movies` | Получить фильмы, применить поиск и фильтры |
| `GET` | `/api/movies/1` | Получить один фильм по `id` |
| `POST` | `/api/movies` | Создать фильм |
| `PATCH` | `/api/movies/1` | Изменить переданные поля фильма |
| `DELETE` | `/api/movies/1` | Удалить фильм |

Пример тела `POST`:

```json
{
  "title": "Интерстеллар",
  "year": 2014,
  "genre": "Фантастика",
  "status": "planned",
  "rating": null,
  "description": "Посмотреть на выходных."
}
```

Полный контракт, ограничения полей и критерии проверки описаны в [ТЗ](TZ.md).

## Проверка проекта

Автоматическая проверка:

```bash
npm run build
npm test
```

Тесты сами запускают отдельный сервер и создают временную SQLite-базу. Рабочая база с вашими фильмами не используется. Проверяются HTTP-операции и ошибки, сохранение после перезапуска, отсутствие повторного заполнения удаленного списка.

Для ручной проверки создайте фильм, измените его, обновите страницу и перезапустите сервер: изменения должны сохраниться. Затем проверьте поиск, фильтры и удаление. Подробный список проверок находится в [ТЗ](TZ.md#9-критерии-приемки).

## GitHub и работа вдвоем

Если вы получили `movielist-project.zip`, внутри находятся папка исходников `movielist/` без `.git` и отдельный `movielist.bundle` с начальной историей Git. Для обычного запуска достаточно папки исходников. Как восстановить репозиторий из bundle или начать историю из исходников, описано в инструкции ниже.

1. [Создание GitRepo и первая отправка на GitHub](docs/GITHUB.md).
2. [Распределение задач и ветки двух участников](docs/TEAM.md).
3. [Сценарий защиты и ответы на вопросы](docs/DEFENSE.md).

`node_modules`, `.next`, `.env.local` и база SQLite исключены из Git. У второго участника после `npm ci` и первого запуска появится собственная локальная база с примерами. GitHub синхронизирует код; список фильмов между компьютерами через Git не передается.

## Границы учебной версии

Это один общий список без регистрации и личных аккаунтов. Проект рассчитан на локальный запуск или Node.js-сервер с постоянным диском. Для публичного многопользовательского сервиса понадобятся авторизация, разделение данных пользователей и соответствующая серверная инфраструктура. GitHub Pages не запускает этот backend.
